White-Label Retail CRM

A single reusable CRM core that ships configured per retail client. SoftMarket KE is tenant #1; the next supermarket is a new Tenant row plus branding/config — not a code fork. It follows a contact-centric 360° model where Contact is the hub and Account, Activity, Lead, and Opportunity all relate to it. Retail retention economics (catch churn early, nurture loyalty, clean vendor relations) drive the design, with Kenyan-market hooks designed in from v1.

Django Python PostgreSQL / Supabase Tailwind HTMX Vercel

What the app does

  • Contact hub (360° view)

    Every customer/vendor in one place with a timeline of every call, email, note, and deal.

  • Multi-tenant white-label

    One codebase serves many clients as isolated instances — each with its own branding and pipeline.

  • Lead capture + BANT scoring

    Public web form turns strangers into scored leads (hot/warm/cold) and routes them by territory.

  • Kanban opportunity pipeline

    Drag deals across stages, see per-stage value totals and a weighted forecast.

  • Activity & follow-ups

    Timestamped log plus a to-do list of next actions linked back to each deal.

  • Retention & churn signals

    Lifecycle tracking flags customers with no recent activity so you re-engage before they leave.

  • Per-tenant configuration

    Each client configures its own pipeline stages and key fields — no code change.

  • Integration hooks

    M-Pesa, WhatsApp Business, eTIMS export, and offline sync wire in as the build progresses.

Already provided by existing SoftMarket codebase

  • Tenant + InstanceScopedModel (multi-tenant base)
  • Contact, Account, Activity, Lead, Opportunity models
  • BANT scoring service on Lead
  • Django JSON API at /api/*
  • Vercel deployment config

Out of scope (v1)

  • Team seats / RBAC — single owner string per record in v1; full multi-user comes when a client needs it
  • Email-blast marketing — only the triggered lead auto-responder ships in v1
  • Inventory / POS module — the CRM is not the store — expose hooks only
  • Custom report builder — ship a fixed set of preset retail reports instead
  • Bi-directional accounting — eTIMS export only, no live ledger sync
  • Native mobile apps — responsive web only in v1
  • In-product AI features — the build uses AI; the shipped CRM does not (future scope)

Data model

What the app needs to remember.

Tenant

slug short id, e.g. 'softmarket'
name display name, e.g. 'SoftMarket Kenya'
brand colors / logo per-instance look so the same UI re-skins
default lead owner who new leads fall to if no territory match
active whether this instance is live

Related to · parent of every other entity — everything below belongs to one tenant

Account

name the company (supplier/vendor)
industry / website / phone basic company facts
billing address where invoices go
notes free text about the relationship

Related to · has many Contacts and many Opportunities

Contact

name / email / phone how to reach the person
date of birth / personal notes context that fuels relationship nurturing
lifecycle subscriber → lead → customer → churned
territory county/region used to route leads

Related to · the hub — has Activities, Leads, and Opportunities

Activity

type call, email, meeting, note, or task
subject / notes what happened
due at for tasks and follow-ups
done whether the task is checked off

Related to · belongs to one Contact

Lead

source / message where it came from and what they said
BANT answers budget, authority, need, timeline — each 1–3
rating hot / warm / cold from the BANT score
owner / auto-responded who it's assigned to and whether the reply sent

Related to · converts into a Contact when qualified

Opportunity

name / amount the deal and its value in KSh
stage where it sits in the pipeline
probability / close date forecast inputs
owner the rep running the deal

Related to · belongs to one Contact and one Account

TenantStage (new in v1)

tenant which instance this stage belongs to
name / order stage label and its position in the pipeline

Related to · makes each client's pipeline configurable — the white-label requirement

Milestones

1

Tenant + Contact/Account CRUD

Lay the white-label foundation and the two core entities every later feature depends on.

What gets built

  • Tenant model + branding hooks (colors, logo)
  • Contact list, detail, create/edit/delete
  • Account (vendor) list, detail, CRUD
  • 360° shell that will later show the timeline

Not in this milestone

  • Leads or deals (those need later milestones)
  • Kanban board
  • Automation/auto-responder

Done when: Logged-in user can create contacts and accounts, open a contact, and see tenant branding applied.

2

Activity log + 360° timeline

Attach the interaction history to each contact so the hub view comes alive.

What gets built

  • Log calls/emails/meetings/notes/tasks
  • Timestamped timeline on the contact page
  • Mark tasks done

Not in this milestone

  • Follow-up reminders/notifications (those are M5)
  • Bulk import UI

Done when: Opening any contact shows every interaction in order, newest first.

3

Lead capture + BANT scoring

Turn the public web form into scored, routed leads without manual triage.

What gets built

  • Public web-intake form
  • Auto BANT score → hot/warm/cold
  • Territory-based auto-assign + auto-responder email

Not in this milestone

  • Lead de-dupe/merge
  • Manual BANT entry UI

Done when: Submitting the form creates a rated lead owned by the right rep with an auto-reply sent.

4

Opportunity pipeline (Kanban)

Give deals a board with drag-and-drop and a forecast.

What gets built

  • Board + list views of opportunities
  • Drag deals across stages (persisted)
  • Drag to reorder within a column
  • Per-stage value totals + weighted forecast
  • Associate multiple contacts with a deal

Not in this milestone

  • Per-deal probability editing UI (default-per-stage used)
  • Custom fields per deal

Done when: User can drag a deal to Won and watch the stage total and forecast update.

5

Follow-ups + churn detection

Make sure nothing falls through the cracks and at-risk customers surface early.

What gets built

  • To-do list of next actions with due dates
  • Check-off that links back to the deal
  • Lifecycle transitions
  • Churn flag on customers with no activity in N days

Not in this milestone

  • Push/email reminders (in-app only in v1)
  • Predictive/ML churn

Done when: A rep sees today's follow-ups and a list of customers who've gone quiet.

6

White-label config + integration hooks

Make the core resellable and wire in the Kenyan-market integrations.

What gets built

  • Per-tenant pipeline stage configuration UI
  • Branding UI (colors/logo)
  • M-Pesa, WhatsApp, eTIMS, offline-sync interfaces + queues

Not in this milestone

  • Live third-party calls for every channel (contracts wired, real creds per tenant later)
  • Full SSO/multi-user

Done when: A second tenant (new row + stages/branding) renders isolated, branded, and integration-ready.
